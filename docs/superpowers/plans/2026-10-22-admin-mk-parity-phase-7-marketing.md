## Review Focus

1. **Tracking off ⇒ public HTML unchanged.** Default settings, and also `consent.enabled=true` with no tracker, render no bootstrap, banner, footer link, tracker or snippet. → Task 5 test `MarketingTracking renders null when inactive` + `CookieSettingsSlot renders null when inactive`, Task 2 `trackingFrame` tests.
2. **Token never leaves the server.** GET after saving a token contains neither the plaintext nor any `v1.` string; omitted `capiToken` keeps it, `null` removes it; audit diff shows only `configured/replaced/removed`; Meta error echoing the token is scrubbed. → Task 3 tests.
3. **No third party before consent.** Fresh visitor (no cookie): bootstrap never appends `gtm.js`; Pixel not loaded; analytics/marketing snippets not rendered; after "Reject all" still none. → Task 2 bootstrap/consent-client tests, Task 5 CustomScripts/MarketingScripts tests.
4. **A lead always saves.** Meta down / 400 / timeout / unreadable token / no key / no consent cookie ⇒ quote or contact still 201; CAPI only for a valid current-version cookie with `m:1`; failure writes `tracking.capi_failed` audit with HTTP status only. → Task 6 tests.
5. **Bad consent cookie ⇒ no consent.** Wrong `v`, older than `reconsentMonths×30` days, >5 min in the future, malformed JSON, >300 chars, id not 1–64 chars ⇒ treated as none (banner shows, GTM not loaded, server sends no CAPI). → Task 2 `readConsent` + bootstrap fixture tests, Task 6 test.

## Rulings (made while planning)

1. `tracking` is **not** a `GLOBALS` key: own schema `TrackingSettings` + `parseTracking`, dedicated API, no revisions (ciphertext must not be snapshotted; MK R11). Keeps the Phase 4 invariant "editable keys = GLOBALS keys".
2. Tracking writes use their own transaction on the `settings` table (as MK) instead of changing the shared `settingsRepository.save` (which always writes a revision).
3. Custom code is **owner-only** (`code.update`), per spec §2.6/§5.3 and the existing role matrix; admins are not granted it although the brief mentioned "owner/admin".
4. Event set is VANTAGE's three spec events; MK's `book_appointment`, `sign_up`, `share` are dropped (no booking/newsletter/articles). `contact_click.method` gains `whatsapp`.
5. Public frame lives in the **marketing layout** inside `<Suspense fallback={null}>` with `await io()` (runtime env for the kill switch, DB settings from tag cache) — not in the root layout, so `/dashboard`, `/login`, `/account` never get trackers. A client-side jump from a non-marketing page into the site starts tracking on the next full load (inline scripts don't run on client renders).
6. No CSP in this phase: VANTAGE has none, and an enforcing CSP during the parallel Cloudinary → R2 move risks breaking images. `CUSTOM_SCRIPT_HOSTS` stays empty (inline snippets only). CSP is a Phase 11 candidate.
7. Consent copy ships with sensible English defaults (Phase 4 rule "defaults render without setup"); the banner stays off until an owner/marketer switches it on.
8. `contact_click` is captured by one delegated listener (no edits to header/footer/contact-info links), keeping Phase 5/8 marketing-component diffs conflict-free.
9. CAPI runs for both quote requests and contact messages, fire-and-forget like `notifyNewQuote`; staff-entered `POST /quotes/admin` never sends CAPI.
10. `track()` pushes to `window.dataLayer` even when tracking is off (MK): it sends nothing anywhere without GTM/Pixel and keeps forms simple.
11. `consent_events` is kept indefinitely (proof of consent, no personal data); no retention job in this phase.
